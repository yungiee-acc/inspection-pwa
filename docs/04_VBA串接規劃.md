# 第四階段：VBA 串接規劃（尚未開始實作）

> **在取得現有 VBA 原始碼前，不假設任何內部程序名稱、資料鍵值或計算方式；也不會修改任何扣重計算邏輯。**
> 本文件只定義「正式報告端」已經備妥的資料契約，以及獨立匯入模組的行為規格。

## 1. 報告端已備妥的資料（正式 Excel 的「VBA匯入資料」工作表）
- 第 1 列＝英文欄位鍵（穩定，VBA 用它找欄位），第 2 列＝中文說明，**第 3 列起是資料**，每一筆已確認配對的查驗一列。
- 33 個欄位，見 `app/js/core/report.js` 的 `VBA_COLUMNS`。重點：
  - `ErpCode`：手機原始選擇的 ERP 品號 → 對應「查驗資料輸入」B8。**不使用**報告顯示名稱。
  - `SampleCode / SampleGrossKg / WaterKg / ImpurityKg / WireKg / Inspector / Note` → B9～B14、B16。
  - `ReportDate / VendorCode / VendorName / VehicleNo / HzShipNo / HzSeqNo / Hz*Kg / HzBricks` → 匯入時用來比對車次。
  - `InspectionID`（+`InspectionRev`）→ 防止重複匯入。 `DataHash`、`ReportVersion`、`ReportStatus` → 確認是最終版本。
  - `ErpWeighTicketNo`：保留空白，等取得 ERP 地磅單號規則。
- 「報告資訊」工作表：版次、審核狀態、審核人、校驗碼、更正紀錄。

## 2. 獨立匯入模組（待實作）的行為規格
1. 讓使用者選取正式報告檔，只接受 `ReportStatus = approved` 且格式版本 `FormatVersion = 1.0`。
2. 讀取「VBA匯入資料」；逐筆在 VBA 的車次清單中比對 **日期、廠商、車號、庫別、地磅資料**（欄位待讀 VBA 後確認）。
3. **只有「唯一確認」的才能寫入**；0 筆或多筆候選 → 列入異常，不寫入。
4. 先顯示**匯入預覽與異常清單**，使用者確認後才寫。
5. 防護：
   - 已匯入過的 `InspectionID`：同 `DataHash` → 略過；`DataHash` 不同（代表報告更正過）→ 顯示差異，需明確確認才覆蓋。
   - 目標車次**已結帳**→ 禁止寫入。
   - 目標欄位已有不同的查驗值 → 顯示並要求確認，不靜默覆蓋。
6. 寫入 B8～B16 後，**呼叫現有 VBA 原本的「儲存」與「重新計算」程序**（程序名稱待讀原始碼後確認），不複製、不改寫扣重公式。
7. 舊版次的報告檔：檔案本身離線無法知道自己已被取代，因此依賴第 5 點的 `DataHash` 比對提示，並建議更正後把舊檔移走。

## 3. 需要你提供
- 最新版 VBA 模組匯出檔（.bas/.cls/.frm）或整個 .xlsm。
- 「查驗資料輸入」B5 車次清單的來源（哪個工作表／欄位）、庫別與地磅資料在哪裡、「已結帳」如何判斷、現有的儲存／重新計算程序名稱。
