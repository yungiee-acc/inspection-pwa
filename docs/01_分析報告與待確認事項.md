### 報告排版規則（由範例反推，已用範例逐格驗證）
- 一趟車（一個出貨序號）的所有品項連續列出，**整趟不跨頁**：該頁剩餘列數不夠就換頁（範例第 1 頁用 9 列、第 2 頁用 6 列）。
- 出貨序號拆成兩格：前 9 碼（A 欄）＋後 2 碼（B 欄，藍字）。
- 回收商、車號只印在該趟第一列。
- 抽驗項目：被抽驗那列 ▓，其餘 □；樣磚代號／毛重／含水／雜質只填在被抽驗那列。含水為 0 時印 `-`。
- 雜質/備註（P 欄）：併車（同車 ≥2 品項）時第一列開頭加「併車:」；雜質種類用「、」分隔。
- 範例的「回收商」欄不是統一規則（呈泓**興業**、協治**企業**、鈞城、金祥達），所以系統用「報告顯示名稱」逐家設定。

## 3. 配對與異常規則（已實作於 `app/js/core/match.js`，有 39 項自動測試）

**候選條件**：日期、廠商（查驗廠商全名＝環資「回收機構」全名）、車號（忽略 `-`、空白、大小寫）、品項（查驗品號的 D 欄名稱＝環資物料名稱）**四項全部相符**。絕不只靠車號。

| 情況 | 系統行為 |
|---|---|
| 唯一候選、一對一 | 「建議配對」；仍需辦公室按確認（可一鍵全確認） |
| 同車同品項有 2 筆以上查驗 | 異常，列出候選讓人選，**不自動選第一筆** |
| 一筆查驗符合多個環資列／同日同車多趟 | 異常，人工指定 |
| 整趟車沒有任何查驗 | 阻擋報告，無放行選項；須補查驗或手動指定 |
| 查驗找不到環資列 | 無歸屬清單，並說明原因（品項不符／車號不符／廠商不符／D 欄空白／已配對給另一筆／環資尚未匯入） |
| 同一趟其他品項沒有查驗 | 視為正常「未抽驗」（範例每趟只抽 1 項） |
| 環資品名不在 D 欄清單 | 阻擋，須管理員確認 |
| 確認後查驗被修改或作廢 | 該配對自動失效，須重新確認 |
| 樣磚毛重與（淨重÷磚數）差距 | 先不啟用（config.js 可開） |
| 協治：環資全名＝A080，查驗選 A051 | 不相符 → 異常（因為 A051 全名是「協治企業股份有限公司(志澄企業有限公司)」，系統不猜） |

## 4. 已確認事項（你已回覆）

- **登入**：三個帳號／角色——一般使用者（現場查驗）、審核者（匯入環資、配對、產生並審核報告）、後台管理者（另可維護品項對照／廠商／使用者、解鎖更正）。審核者與後台管理者都能審核。登入技術仍是 Supabase Email＋密碼（若要改成別的方式再說）。
- **同車多品項不算異常**：只做資訊標示，依品項自動配對（仍須審核者確認）。
- **報告一天一個檔**（工作表名 1151109）。
- **整車一定有一個品項要查驗**；其餘未查驗品項視為未抽驗。整車沒有任何查驗時沒有放行選項，必須補查驗（或手動指定）才能出報告。
- **審核者可審核自己製作的草稿**（先維持可以）。
- **雜質種類複選欄、備註一併印在 P 欄**：OK。
- **其餘廠商的報告顯示名稱**：首次出報告時再設定（管理→廠商）。
- **樣磚重量合理性門檻先不設定**：只保留硬性檢查（必填、不可負數、含水＋雜質＋鐵絲須小於毛重）；門檻在 `config.js` 設為 null，日後填數字即啟用。

1. **重量小數位**：最多 2 位。報告毛重顯示 1 位（512.5、521.0）、雜質 2 位（3.45），依範例格式。
2. **鐵絲重**：範例報告沒有此欄，只放進 VBA匯入資料（B16）。
